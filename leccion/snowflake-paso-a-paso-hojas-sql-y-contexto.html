Hojas SQL y el contexto - rol, warehouse, base y esquema

Las worksheets son donde se escribe y ejecuta SQL. Creas una hoja, entiendes los cuatro datos de contexto que decide cada consulta (rol, warehouse, base y esquema), ejecutas la sentencia del cursor o todas, y lees el resultado con su Query ID, duración y filas.

▶ Abrir la lección interactiva (4 ejercicios)

Al terminar vas a poder

  • Crear y nombrar una hoja SQL
  • Entender el contexto de la sesión
  • Ejecutar una sentencia o todas
  • Leer el resultado y los Query Details
🧠 Las cuatro preguntas antes de cocinar

Cada consulta responde cuatro preguntas antes de empezar: quién cocina (el rol, que decide qué puede tocar), con qué hornalla (el warehouse, que pone el cómputo), en qué despensa (la base) y en qué estante (el esquema). Si una falta o está mal, la receta falla aunque el SQL esté perfecto.

Paso 1 — Una hoja nueva

+ SQL Worksheet (o Create → SQL Worksheet). Ponle nombre y escribe:

-- Pedidos de la tienda por canal de venta
SELECT canal, COUNT(*) AS pedidos
FROM pedidos
GROUP BY canal
ORDER BY pedidos DESC;

Paso 2 — El contexto

Cada consulta corre con cuatro datos de contexto:

Dato Qué decide Cómo se cambia
Rol Qué puedes ver y hacer USE ROLE sysadmin; o el selector
Warehouse Con qué cómputo corre (y quién paga) USE WAREHOUSE compute_wh;
Base Dónde buscar las tablas sin nombre completo USE DATABASE tienda_andina;
Esquema Ídem, dentro de la base USE SCHEMA tienda_andina.public;

Como el contexto es TIENDA_ANDINA.PUBLIC, FROM pedidos encuentra TIENDA_ANDINA.PUBLIC.PEDIDOS.

Paso 3 — Ejecutar

Atajo Qué ejecuta
Ctrl+Enter o ▶ La sentencia donde está el cursor (o lo seleccionado)
Ctrl+Shift+Enter o Run all Todas las sentencias de la hoja, en orden

Paso 4 — El resultado

El Query ID identifica la consulta para siempre: sirve para buscarla en el historial, para Time Travel (nivel 4) y para pedir ayuda a soporte.

💡 El warehouse se prende solo

Si el warehouse estaba suspendido, la primera consulta lo enciende (AUTO_RESUME). Por eso la primera puede tardar un segundo más.

🐞 Errores frecuentes
  • Ejecutar con el rol equivocado. Un "does not exist or not authorized" muchas veces es el rol de la hoja, no el nombre de la tabla.
  • No tener warehouse elegido. Sin warehouse, la consulta no puede correr: "No active warehouse selected".
  • Ejecutar todo cuando querías una sentencia. Ctrl+Enter corre la sentencia del cursor; "Run All" corre la hoja entera, incluidos DROP o DELETE que dejaste más abajo.

✅ Lo que lograste

  • Creaste una hoja y ejecutaste SQL.
  • Entiendes el contexto de la sesión.
  • Lees el resultado y el Query ID.
